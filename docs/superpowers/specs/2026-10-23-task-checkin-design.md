## 1. 範圍

在 MuMu 班級工作台新增「任務打卡」模組。模組分成兩個系列，共用工作台的班級名單：

| 系列 | 分頁 | 一句話 |
|---|---|---|
| 一般任務 | 打卡台、缺交總覽、學生歷程、封存紀錄 | 老師設定最多 4 項任務，學生點自己的名字打卡 |
| 中午時段 | 中午打卡台、每日結算、學生歷程、每日封存 | 每天 5 項固定任務，12:40 截止，17:00 自動結算並封存 |

**和作業小管家分開**（老師第 1 題）。任務打卡給學生看、由學生操作，用途是讓學生確認自己完成並繳交；作業小管家是老師自己管理訂正與登記成績用的。兩個模組不共用資料，也不互相串接。

**不在範圍內**
- 畫面上的「從備份還原」（第 21 題）。需要救援時由開發者處理，和主文件 D11 一致。
- 搬移舊原型的資料，包括六任務版的備份（第 5 題）。
- 沒有使用的日子補建空白紀錄（第 9 題）。
- 17:00 封存後的更正，唯一的例外是補標請假（第 17 題、追問 4）。

## 3. 系統定位

### 3.1 放在工作台裡

- 沿用工作台的登入、班級、名單（`students`）、SaveStatus、`audit_log` 和每晚備份。
- 左側選單新增「✅ 任務打卡」，路由前綴 `/checkin`。
- 老師在自己的手機或電腦上，跟使用其他模組一樣，可以看所有分頁、操作所有功能，不需要 PIN。

### 3.2 教室模式

iPad 會投到電子白板給全班操作，所以要防止學生點進 MUMU 幣、設定這些地方。做法是「教室模式」：

- 在 `/checkin` 頁面上按「進入教室模式」，iPad 就會記住這個狀態（localStorage 的 `mumu.classroom`）。要先在設定頁設好 PIN，這個按鈕才能用。
- 教室模式下：
  - 隱藏工作台的側欄和底部分頁；
  - 只能看到任務打卡的 8 個分頁，其他路由一律導回 `/checkin`；
  - 頂端是一列精簡的標題列（§7.2）。
- 按標題列的「🔒 老師」，輸入 PIN 就能解鎖老師工具列。解鎖後 2 分鐘沒有操作會自動上鎖，也可以手動按「上鎖」。
- 要用 PIN 解鎖的功能：編輯任務、單項封存、整輪封存、標免交、標請假、補登、結算、離開教室模式。「名單與設定」「備份資料」這兩個按鈕會先離開教室模式，再前往 `/settings`。
- 「匯出」和瀏覽各分頁不需要 PIN。

**PIN 是防止誤按，不是資安措施。** 這台 iPad 本來就登入著老師的帳號；PIN 只是讓學生不會在白板上誤按老師的功能。所以 PIN 在前端比對就好：
- 存法：4 位數，存成 SHA-256（加上隨機 salt）的雜湊，放在 `checkin_settings`。
- 輸入方式：畫面上的大數字鍵盤，不叫出系統鍵盤。
- 忘記 PIN：老師在手機上登入工作台，到設定頁重設。

### 3.3 白板觸控的限制

白板的觸控是透過 USB-HID 傳回 iPad 的，iPadOS 很可能把它當成「指標點擊」，而不是手指觸控。介面規則如下：

- 所有操作都是**單點**。不用長按、滑動、雙擊、捏合，也不靠 hover 才顯示資訊。
- 姓名按鈕至少 30pt 高，按鈕之間至少留 6pt。白板的觸控校準可能有偏差，按錯了靠「復原」補救。
- 同一顆按鈕在 600ms 內又被點一次，第二次忽略，避免白板把一次觸控送成兩次點擊。
- 寫入動作送的是「設為完成／設為未完成」，不是「切換」，所以重送也不會變成相反的結果（§6.1）。
- C1 上線後，第一件事是請老師在教室實際試用，確認點擊會落在正確的名字上（§12）。

## 4. 時間規則

- **時間一律以資料庫為準。** 打卡時間由 RPC 用 `now()` 寫入，日期和時刻換算成 `Asia/Taipei`。iPad 的時鐘就算不準，也不影響判定。
- 畫面右上的時鐘：頁面載入時向伺服器取一次時間，算出和裝置時鐘的差，之後用「裝置時間 + 差值」顯示。17:00 切換成唯讀也用這個時間。
- **準時判定**：`date_trunc('minute', 台北時間的打卡時刻) <= 截止時間`。截止 12:40 時，12:40:59 算準時，12:41:00 算逾時。
- 老師補登的中午任務，不看時間，一律算逾時（第 16 題）。
- **17:00 之後**，當天所有打卡、取消、復原、補登都由 RPC 拒絕，就算排程還沒跑也一樣。唯一的例外是補標或取消請假。
- 一般任務沒有截止判定，也沒有 17:00 鎖定。

### 5.5 名單異動（trigger 掛在 `students`）

| 事件 | 一般任務（進行中） | 中午（今天，尚未封存） |
|---|---|---|
| 新增學生 | 每項進行中的任務都補一列 `pending`（第 13 題） | 今天已經有紀錄的話，補進名單和打卡列 |
| 設為轉出（`left_at`） | 對應的列填 `removed_at` | 對應的列填 `removed_at` |
| 復學 | 清掉 `removed_at` | 清掉 `removed_at` |
| 改姓名或座號 | 不動；快照在封存時更新 | 不動；以當天的快照為準 |

- 同座號換人，就是「舊學生轉出＋新增一位學生」。兩個人是不同的 `student_id`，紀錄不會合併（第 12 題、AC36）。
- 這些打卡表對 `authenticated` 只開放讀取（§5.6），所以這個 trigger 要用 `security definer` 執行，並且只處理同一個 `owner_id` 的資料。

### 5.6 權限

- RLS 比照主文件 §5.7：`owner_id = auth.uid()`，子表寫入時也要檢查父表屬於同一位老師。
- **`checkin_task_marks`、`noon_days`、`noon_day_*`、`noon_marks`、`checkin_events` 只開放 `select`。** 寫入只能透過 §6 的 RPC。這些 RPC 用 `security definer`，第一行先檢查資料屬於 `auth.uid()`。
  - 這和主文件「RPC 一律 security invoker」不同。原因是打卡時間、17:00 鎖定、事件紀錄必須在同一個 transaction 裡由伺服器決定，不能讓前端（包括有 bug 的前端）繞過去。
- `checkin_settings`、`checkin_tasks`（名稱、日期、說明）、`noon_items` 可以直接寫，比照其他模組。

## 6. RPC 與排程

### 6.1 一般任務

| RPC | 說明 |
|---|---|
| `task_create(class_id, slot, name, task_date, due_date, note)` | 在同一個 transaction 裡，為在籍學生各建一列 `pending` |
| `task_set_done(task_id, student_id, done bool)` | 冪等：已經是目標狀態就不寫入，也不記事件。done 時寫入 `now()`。回傳新的狀態和事件 id |
| `task_set_exempt(task_id, student_id, exempt bool)` | 只有老師用 |
| `task_archive(task_ids uuid[], kind)` | 建一個批次，更新姓名快照，把任務設為 archived，騰出格子 |
| `checkin_undo(event_id)` | 共用（§6.3） |

### 6.2 中午

| RPC | 說明 |
|---|---|
| `noon_today(class_id)` | 回傳伺服器時間；今天有紀錄就回傳紀錄，沒有就回傳範本加名單的預覽。不寫入 |
| `noon_set_done(class_id, template_id, student_id, done bool)` | 今天還沒有紀錄就先建立（§5.3），再依 §4 判定 ontime 或 late。17:00 之後拒絕 |
| `noon_teacher_fill(class_id, template_id, student_id)` | result 一律是 late，source 是 teacher。17:00 之後拒絕 |
| `noon_set_leave(day_id 或 class_id+date, student_id, on_leave bool)` | **封存後也可以用**。如果當天已經封存，就重算 `final_summary`、更新 `revised_at`，並記一筆 actor 為 teacher 的事件 |
| `noon_settle(class_id)` | 計算統計，寫進 `settled_*` |
| `noon_archive_due()` | 給排程用；見 §6.4 |
| `noon_archive_due_mine()` | 給前端用；邏輯相同，只處理自己的班級，`archived_by` 一律是 catchup |

### 6.3 復原

- 「復原上一步」只復原**這台裝置**最近一次的打卡或取消。它是畫面上一直顯示的按鈕，例如「↶ 復原：學生28 閱讀認證」，下一次操作後就換掉。不是幾秒後就消失的 toast。
- `checkin_undo(event_id)`：只有當目前狀態還等於該事件的 `next` 時，才還原成 `prev`，包括原本的 `done_at` 和 `result`，並記一筆 `undo` 事件。如果狀態已經被別的操作改掉，就拒絕，畫面提示「狀態已變動，無法復原」。
- AC17 的兩種情況都由這個規則處理：
  - 取消之後重新打卡：用重新打卡的時間判定。
  - 取消之後按復原：恢復原本 12:39 的時間，維持準時。

### 6.4 17:00 封存

- 用 pg_cron 每 5 分鐘呼叫一次 `noon_archive_due()`（`*/5 * * * *`，排程本身以 UTC 計時）。每次只做一個有索引的查詢，成本可以忽略。
- 處理對象：`status = 'open'`，而且「日期早於今天」或「日期是今天、台北時間已過 17:00」的那幾天。逐筆 `select … for update`，算出 `final_summary`，設為 archived。
  - `archived_at - scheduled_archive_at ≤ 15 分鐘` 標成 schedule，否則標成 catchup。
- 冪等：只處理 `status = 'open'` 的資料，重跑或重試都不會多出第二份，筆數也不會增加（AC26）。
- 前端打開中午頁面時，也會呼叫 `noon_archive_due_mine()`。排程失敗時由這裡補做，畫面標示「於 10/24 08:00 開啟時補封存」（M08）。
- 封存一定用當下最新的打卡重算，不用手動結算的結果（N10、AC22）。

/checkin/noon/archive    每日封存（M08）
/settings                新增「任務打卡」區塊：PIN、中午固定任務、午餐時序

### 7.2 尺寸目標

- 驗收基準：iPad (A16) 橫向，版面 1180×820pt，**從主畫面開啟的全螢幕模式**。扣掉狀態列，可用高度約 796pt。
- 在 Safari 分頁裡開時有網址列，允許上下捲動。要請老師把網站「加入主畫面」。
- 教室模式的標題列只有一列，高度 ≤ 56pt，內容依序是：站名、系列切換（任務打卡｜中午時段）、分頁、時鐘、🔒 老師。Mockup 中的大標題和副標題，在教室模式下拿掉。

| 畫面 | 版面 | 30 人時的估算高度 |
|---|---|---|
| 一般打卡台 | 2×2 張卡片；每張卡片的名字排 6 欄 × 5 列，按鈕高 44pt | 標題列 56 + 卡片 2×336 + 間距 ≈ 760pt |
| 中午打卡台 | 午餐時序和圖例併成一列；5 項任務各一列，左邊 150pt 放任務名稱，右邊名字排 10 欄 × 3 列，按鈕高 32pt | 56 + 48 + 5×116 + 間距 ≈ 740pt |

- 姓名在卡片內全部展開，卡片內沒有捲軸（C07、AC02）。名單超過 30 人時，列數會增加，允許整頁捲動。
- 老師在手機上看時用一般的工作台版面：卡片改成直向排列，可以捲動。

### 7.3 各頁重點

- **一般打卡台**
  - 卡片顯示「完成數 / 應完成數」，應完成數不含免交和轉出的學生。
  - 卡片底部的「未完成 N 人 →」連到缺交總覽，並預先篩選這一項。
  - 空格顯示「尚未設定」，老師解鎖後可以新增任務。
  - 「編輯」裡可以改名稱、日期、說明，可以標免交，也有「封存這一項」（第 24 題）。
  - 「封存本輪紀錄」要 PIN，並跳出確認視窗。
- **缺交總覽**
  - 範圍可以選「進行中」或某一個封存批次。
  - 可以切換全部任務或單一任務，也可以搜尋座號或姓名。
  - 卡片上列出缺交的任務和缺幾項；「查看個人歷程」連到學生歷程頁。
- **學生歷程（一般）**
  - 上方是摘要：完成幾項、未完成幾項。
  - 中間是逐項表格：日期、任務、狀態、打卡時間、來源（進行中或封存批次）。
  - 下方是**完整的**操作歷程，依時間新到舊（第 23 題）。
- **中午打卡台**
  - 準時用綠色加 ✓，逾時用橘色加「逾」，未完成用白色，請假用灰色加「假」。顏色之外一定有文字或圖示，不靠顏色辨識。
  - 17:00 之後整頁唯讀，頂端顯示「今天已於 17:00 封存・以下為唯讀紀錄」（M09）；老師解鎖後只能補標請假。
- **每日結算**
  - 顯示最近一次結算的結果。如果結算之後資料又有變動（`version > settled_version`），就顯示「打卡已更新，請重新結算」。
  - 頁面上有全班各項任務和每位學生兩張表；請假的學生顯示「請假」，不算比率。
- **學生歷程（中午）**：可以選學生和日期，顯示 5 項任務的截止時間、狀態、打卡時間，以及完整的操作歷程。
- **每日封存**
  - 日期由新到舊，每一天顯示人數、準時率、逾時率、排定時間和實際執行時間。
  - 補做的封存用橘色字標示；封存後改過請假的，標示「已於 …… 修改請假」。

### 7.4 讀取與更新

- 打卡台用樂觀更新：點下去的瞬間，先用伺服器時間差推算的時間決定顏色；RPC 回傳後再以伺服器的 result 為準。如果寫入失敗，就還原畫面，交給 SaveStatus 處理重試（主文件 §9）。
- 回到前景（`visibilitychange`）時重新讀取資料，因為 iPad 休眠後頁面可能是舊的。打卡台另外每 60 秒重新讀取一次，讓老師手機上的改動也會出現在白板上。
- 第一版不用 Supabase Realtime。

## 8. 統計公式

- **中午，單項任務**：分母 = 當天名單中「沒請假、沒轉出」的人數。準時率 = 準時數 ÷ 分母，逾時率和未完成率同理，總完成率 = (準時 + 逾時) ÷ 分母。
- **中午，個別學生**：分母 = 當天的任務數，目前是 5。請假的學生不計算。
- **中午，全班合計**：把各項任務的數字加總後再除。
- 每個學生在每一項任務只會是準時、逾時、未完成、請假其中一種，前三種加起來一定等於分母（§10 的資料庫測試會檢查）。
- **一般任務**：完成率 = 完成 ÷ (全部 − 免交 − 轉出)。
- 只在顯示時四捨五入到小數 1 位；分母是 0 時顯示「0%・0 筆」。
- 統計由 SQL 函式 `noon_compute_summary(day_id)` 算出，結算和封存都用它。打卡台上的即時計數由前端的純函式（`features/checkin/logic/stats.ts`）計算。兩者用同一組測試案例互相比對。

## 9. 匯出與備份

- **匯出 Excel**（第 26 題）：用 `write-excel-file` 產生，只在按下匯出時才動態載入，不增加首次載入的大小。
  - 缺交清單：座號、姓名、缺交任務、缺幾項、範圍。
  - 一般任務個人紀錄：日期、任務、狀態、打卡時間、來源。
  - 中午每日統計（規格書 §6）：日期、統計對象、座號或任務、準時、逾時、未完成、請假、應完成數、三種比率。
  - 中午個人歷程：再加上截止時間、實際打卡時間、完成狀態、封存狀態。
- **備份**
  - 把新的資料表加進 `scripts/backup.mjs` 的 `TABLES` 和設定頁的 `BACKUP_TABLES`。
  - `checkin_events` 一年大約 5 萬筆以上，必須分頁讀取。
  - **既有問題：** 設定頁的手動備份用 `.limit(50000)` 一次讀完，但 Supabase 的 `max_rows` 是 1000（本機設定是這樣；正式站的設定還沒確認），超過的列會被直接截掉，而且不會報錯。這要另外修，不在本模組範圍。本模組的備份和查詢一律分頁讀取。
- **還原**：沒有畫面上的還原。AC31–33 改成「下載備份，在 dev 或本機 Supabase 演練一次由開發者還原，比對筆數」。

## 10. 測試

| 層級 | 內容 |
|---|---|
| 單元（Vitest） | 統計與四捨五入；分母是 0；請假和免交不算分母；版面欄列數的計算；同一顆按鈕 600ms 內連點只算一次；PIN 雜湊比對；匯出的欄位 |
| 資料庫（SQL 測試） | 見下方 |
| 瀏覽器實測 | iPad 1180×796 下兩個打卡台不捲動；手機寬度可以正常捲動；教室模式擋住其他路由；PIN 解鎖後 2 分鐘自動上鎖 |
| 實機 | 在老師的教室，用 iPad＋HDMI＋電子白板實際點一輪（§12 C1） |

資料庫測試的內容：
- RLS 隔離：另一個帳號讀不到、寫不進這些表，也不能直接 update marks。
- 判定時間點：12:39:59、12:40:59 算準時，12:41:00、16:59:59 算逾時，17:00:00 拒絕寫入。
- 補登一律算逾時。
- 取消之後重打，以及取消之後按復原。
- 冪等：同一個設定重送兩次，只有一筆事件。
- 排程重跑三次，只有一份封存。
- 跨日補做時，`archived_by` 是 catchup，原本的打卡時間不變。
- 封存後補標請假，`final_summary` 會重算。
- 名單 trigger：新增學生、轉出、復學。
- 快照：改範本或改名之後，舊日期不變。

**可控的測試時鐘：** 每個寫入 RPC 都拆成兩層：
- 內部函式 `_noon_set_done(…, p_at timestamptz)` 接收時間參數，不授權給 `authenticated`；
- 公開的 `noon_set_done(…)` 呼叫它時傳入 `now()`。

SQL 測試直接呼叫內部函式，就能指定時間。前端和一般使用者無法偽造時間。

## 14. 風險

| 風險 | 對策 |
|---|---|
| 白板觸控以指標事件送進 iPad，行為和手指觸控不同 | 只用單點；C1 上線後先在教室實測（AC44） |
